# User Template Intake

Use this workflow when the user uploads or references a PPT/PPTX deck they like and wants to use it as a template, visual reference, or style direction.

This is allowed for a user's own project when rights and confidentiality are clear. It is not allowed to redistribute the uploaded template in this public repository.

## Why This Matters

Original template recipes are useful for public release, but they can produce simple or generic results when the user expects a richer visual system.

User-provided reference decks can improve:

- page variety;
- layout richness;
- typography hierarchy;
- chart and table styling;
- chapter rhythm;
- color and spacing consistency;
- editability through real slide masters and layouts.

## Intake Questions

Ask or infer:

- Did the user create or license this template?
- Is it allowed for this project or only for inspiration?
- Can the deck be used as a real PPTX template, or should it only inform a new original recipe?
- Does it contain private business content that must be removed or ignored?
- Which pages does the user like and why?
- Which parts should not be copied?
- Should the output preserve PowerPoint editability?

## Classification

Classify the uploaded deck as one of:

| Class | Meaning | Allowed Use |
|---|---|---|
| owned-template | user owns or is authorized to use it | can build from the PPTX for this private project |
| licensed-project-template | licensed for this specific project/user | can use within confirmed scope |
| inspiration-only | user likes the look but rights are unclear | extract abstract style rules only |
| confidential-reference | contains private material | use only in local/private session; do not publish |
| forbidden | user cannot confirm rights or asks to redistribute | do not use or copy |

## Extraction Targets

When allowed, extract:

- slide size and aspect ratio;
- slide masters and layouts;
- color palette;
- font families and hierarchy;
- title/body/caption styles;
- spacing and grid;
- recurring page types;
- chart and table styles;
- section divider patterns;
- icon and image treatment;
- speaker notes conventions;
- animation or transition rules if relevant.

Do not extract or reuse:

- confidential content;
- logos unless authorized;
- commercial illustrations or icons without rights;
- proprietary screenshots;
- copied marketplace template files for redistribution.

## Template Use Modes

| Mode | Use When | Output |
|---|---|---|
| template-build | user has rights and wants editable PPTX | use actual master/layouts where tools allow |
| style-extract | rights are unclear or user wants inspiration only | create an original style recipe from abstract traits |
| page-pattern-library | user likes selected page types | define reusable page patterns without copying content |
| hybrid | combine user template traits with original recipe | new visual direction with clear boundaries |

## Page Pattern Library

Convert useful pages into abstract patterns:

- title / cover;
- agenda;
- section divider;
- executive summary;
- KPI dashboard;
- comparison matrix;
- timeline;
- roadmap;
- risk heatmap;
- decision page;
- case/story page;
- closing page.

Each pattern should include:

- purpose;
- layout structure;
- required content;
- visual hierarchy;
- editable elements;
- when to use;
- when not to use.

## Workflow

1. Inventory and classify the uploaded deck.
2. Confirm rights and confidentiality boundaries.
3. Select use mode: template-build, style-extract, page-pattern-library, or hybrid.
4. Extract style tokens and page patterns.
5. Create or update the visual recipe.
6. Build 1-2 sample slides using the chosen mode.
7. Ask for approval before bulk production.
8. Record what was extracted and what must not be reused.

## Public Repository Rule

Never commit uploaded user templates, screenshots, extracted media, brand files, or proprietary layout files to the public repository.

Allowed public outputs:

- generic workflow instructions;
- abstract style extraction checklist;
- fictional examples;
- original recipes inspired by broad design principles.

Not allowed:

- the uploaded PPTX file;
- screenshots of the uploaded deck;
- direct page clones;
- commercial template assets;
- private brand systems.
