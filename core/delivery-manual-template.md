# Delivery Manual Template

Every completed skill or workflow must include a delivery manual.

Use this template for public GitHub skills, local skills, agent workflows, and internal automation packages.

## 1. Delivered Scope

State what was delivered and what problem it solves.

Include:

- skill or workflow name;
- intended users;
- primary use cases;
- non-goals;
- public/private boundary.

## 2. Delivered Files

List important files and folders.

Include:

- entrypoint files;
- core workflow or reference files;
- adapter files;
- scripts;
- examples;
- generated packages if applicable.

## 3. Installation Or Setup

Explain how to install, copy, configure, or start using the delivery.

Include:

- commands;
- target paths;
- environment assumptions;
- optional configuration;
- rollback or uninstall notes when needed.

## 4. Usage

Explain how the user should invoke or operate the skill/workflow.

Include:

- example prompts or commands;
- expected first response;
- supported modes;
- required inputs;
- output formats.

## 5. Validation Performed

List exactly what was checked.

Include:

- static validation;
- package validation;
- behavior tests;
- file existence checks;
- security or sensitive-content scans;
- manual review where applicable.

## 6. Known Limitations

State what is not guaranteed.

Include:

- tool availability limits;
- model quality limits;
- manual confirmation gates;
- unsupported formats;
- licensing or confidentiality constraints.

## 7. Maintenance Notes

Explain how to keep the delivery usable.

Include:

- files to update when behavior changes;
- test prompts or smoke tests to rerun;
- release process;
- owner or maintainer notes;
- next recommended improvements.

## 8. Handoff Checklist

- Delivery manual is present.
- README or main handoff links to the delivery manual.
- Installation or setup path is clear.
- Validation status is documented.
- Known limitations are documented.
- Sensitive/private material boundaries are documented.
- Next actions are documented.
